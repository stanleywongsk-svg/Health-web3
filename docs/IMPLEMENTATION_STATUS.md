## Recovery checkpoint — 2026-09-20

The mobile app now uses tested consent and sync controllers in its live hook: server-confirmed local consent can survive an offline relaunch; editable drafts cannot grant access; a local withdrawal overrides stale server state; every reconnect pauses cloud actions until a fresh response. Authentication/invalid-response/storage errors fail closed. Account-generation checks prevent late errors or deletion stages from acting on a replacement account.

Today/previous-day sync uses eligible native-sample observation time, an account/day revision counter reconciled with accepted server summaries, and an in-memory retry operation. A lost response reuses the exact summary/revision and claim key; a failed canonical refresh does not repeat a completed claim. Pending payloads are not persisted. Reinstall/another device cannot automatically recover its source pin, and keychain metadata cleanup remains open.

A forward migration keeps pure consent withdrawal available after the ordinary consent budget is exhausted and checks implicit weekly rewards against their own pinned deadline. The original migration and posted accounting history are not rewritten. Core UI remains Simplified Chinese, only B/C own requirements, and no Lab or future-token path was added.
