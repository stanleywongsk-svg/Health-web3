1. 从经核验的 GitHub 备份在无空格路径全新 clone，按 [CONTINUE_PROMPT.md](CONTINUE_PROMPT.md) 安装锁定依赖，重跑上述全部基线。数据库测试只能使用新建、明确可丢弃的本地 `healthloop_test_*` 库，不能恢复执行旧测试库的破坏性重置命令。
2. 分开检查宿主与代码：Docker 正常后跑真正本地 Auth/Edge；Xcode 首次设置和 CoreSimulator 正常后重装 Pods、编译，再按 [NATIVE_VERIFICATION.md](../apps/mobile/NATIVE_VERIFICATION.md) 做两台 iPhone 验收。宿主阻塞只记录实际错误，不循环启动安装器或声称原生通过。
3. 不依赖宿主修复即可继续 P21：新增前向迁移与实际数据库回归，完成申请者/审批者分离、日/周补偿分录、不可覆写审计、负余额禁止消费。再推进 P20/P22 管理流程、P16/P17 移动端奖励、P25/P27 删除与还原，以及元数据清理、赞助、通知、指标和可及性。
4. 核心验收依赖满足后推进独立 Lab 的本地合成实现。所有外部动作分别确认现有授权，P1/P2 继续保留为条件项。

旧机器的绝对目录、临时 worktree、历史 staging、已停止的测试 PostgreSQL 及运行时缓存可能全部不存在。历史证据中的旧命令仅用于审计，不能直接复制为恢复步骤；使用本报告的相对链接和接续 prompt，从安装与新建可丢弃环境开始。真实设备所需本地配置、公开客户端 key 与签署条件由操作者安全提供，私密 key 不进入 GitHub 或对话。本机清理后不会自动继续运行任务。
