# HealthLoop：香港 App Store 上架方案研究

查核日期：2026-10-05。範圍：iOS、香港 storefront、成人健康習慣產品。這是政策研究與產品建議，不是 Apple 預先批准；本次沒有提交 App、變更產品程式或再次修改 AGENTS.md。

後續採納紀錄：用戶其後已要求按本建議修改整個 App；該實作已更新 `AGENTS.md`、原生介面、固定發布能力、伺服器成就及示範兌換限制。最新進度／測試見 `IMPLEMENTATION_STATUS.md` 與 `TEST_EVIDENCE.md`，本研究以下的「尚未修改」措辭僅描述當時研究階段。未實作廣告、付款、NFT 或錢包供應商。

## 建議採用的產品組合

首版保留現有步行核實、非現金積分、平台徽章和私隱管理。先完成真機與發布驗證；獎勵廣告、付費內容和收藏展示作為可獨立驗證的後續功能。

| 原構想 | 建議的 iOS 方案 | 判斷性質 |
|---|---|---|
| 購買 NFT 提高步行獎勵 | 使用普通平台徽章；NFT 不改變任務資格、積分倍率或上限 | 根據 NFT 功能限制的產品建議 |
| 連接錢包取得加成 | 如保留錢包，只用於自願的收藏查看；不作為基本使用或加成條件 | 避免以錢包解鎖功能的設計建議 |
| 看廣告換獎勵 | 可選廣告換取本人使用的 App 內外觀點；與將來可能兌換其他利益的積分分開 | 有條件可行，須驗證廣告平台與私隱流程 |
| 步行／廣告換代幣 | 維持非鏈上、不可轉讓的積分，不提供兌幣或網頁領幣路徑 | 任務派幣條款下的高風險設計不納入首版 |
| 付費增值 | StoreKit 購買立即可用的主題、內容或具持續價值的會員服務 | 建議的營收替代方案，尚未實作 |
| 保留 Web3 研究 | 獨立網站／Lab、獨立身份與資料、合成任務；不接收健康積分權益 | 延續現有專案隔離邊界 |

## 支持判斷的官方規則

Apple 3.1.1 允許透過 IAP 提供 NFT 相關交易服務，但不允許 NFT 持有權解鎖 App 功能，亦限制以加密貨幣／錢包自行解鎖功能。3.1.5(v) 限制加密貨幣 App 以完成任務派幣；步行不是條文列出的例子，因此本報告對步行換幣的風險判斷屬推論。3.2.2(x) 明確容許觀看廣告等 App 內行為的獎勵。3.1.2(a) 要求用戶取得已購買的訂閱利益時不用再完成其他任務。[Apple 審核指引](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)

因此，透過 IAP 買 NFT 仍不能被當作 NFT 加成的通行證；本研究亦不建議把「日後運動才有機會得到加成」當作付費會員的全部價值。這是 HealthLoop 的產品建議，不是保證過審的配方。

香港方案不採用 App 內 NFT 市場外購按鈕。美國 storefront 有外購連結例外，不能套用到香港；該例外也沒有明確取消 NFT 持有權解鎖功能的限制。[Apple 美國區更新](https://developer.apple.com/news/?id=9txfddzf)、[現行付款規則](https://developer.apple.com/app-store/review/guidelines/#link-to-other-purchase-methods)

## 健康資料與廣告如何分開

使用 HealthKit 的 App 可以展示廣告，但不能使用健康資料來投放廣告。步數、達標狀態、睡眠、心率和推導標籤都不應進入廣告請求或廣告商報表；用戶同意亦不是健康定向廣告的豁免。[Apple HealthKit 私隱文件](https://developer.apple.com/documentation/healthkit/protecting-user-privacy)

健康資料直接為本人帶來利益，須符合由利益提供實體提交、披露讀取資料及不向第三方分享健康資料等條件；雲端託管與供應商資料流仍需逐項核查。[Apple 5.1.3(i)](https://developer.apple.com/app-store/review/guidelines/#health-and-health-research)

若採用 AdMob，獎勵不可是現金、加密貨幣或禮品卡；非金錢獎勵須限本人、不可轉讓並在發布者平台使用。不能因稱為「積分」便再讓它換可轉售 NFT。廣告需清楚交代獎勵、由用戶自願選擇，完成承諾條件後兌付。[Google 獎勵廣告政策](https://support.google.com/admob/answer/7313578?hl=en)

建議先做「看廣告 → 獲得可立即使用的外觀點」。如另做「看廣告＋運動達標 → 加成」，應另行向平台核對組合條件、說明額度與有效期，不能宣稱此混合模式已獲特別批准。廣告入口不因健康結果改變投放；發獎服務只接收最小完成證明。採用短效單次 nonce、服務端驗證、去重及重試測試，不把帳號、錢包或健康任務 ID 放入廣告資料。

拒絕 ATT 追蹤不能成為失去功能或獎勵的理由；「非個人化廣告」名稱本身不能證明 SDK 沒有追蹤。送審前需核對實際 SDK 封包、privacy manifest 和 App Privacy 申報。[Apple 私隱與資料使用 FAQ](https://developer.apple.com/app-store/user-privacy-and-data-use/)

## 可執行的落地順序

1. **發布規則**：為 iOS 建立明確的發布能力清單。首版只開已完成的健康／積分流程；服務端同樣拒絕 NFT、錢包或鏈上餘額導致的加成。不能只移除畫面按鈕而留下可用的發獎接口。研究功能與發布功能分開記錄。
2. **App 內商業模式**：如選付費內容，使用 StoreKit 交易驗證、恢復購買與退款處理。購買成功即可取得內容；運動積分獨立累積。[Apple IAP 文件](https://developer.apple.com/in-app-purchase/)
3. **廣告獨立驗證**：先測非健康定向請求、無健康欄位與可關聯身份、ATT 拒絕流程、伺服器偽造／重播拒絕、一次發獎，以及取消觀看仍能使用基本功能。驗證完成前不把廣告列為已提供功能。
4. **首版實用性**：讓徽章與日常習慣流程具有真正可用價值；不把尚未開放的示範券或 NFT 購買描述成可使用的商業服務。App、網站與商店描述使用一致的積分規則。
5. **送審證據**：完成簽名與兩部 iPhone 的 HealthKit 核實、資料刪除／匯出、私隱政策與供應商清單。準備審核可用的登入方式、可連線後端及清楚的 Review Notes；如使用演示資料，保持可見標示與隔離，不能寫入 HealthKit。依實際功能提供測試步驟，不加入萬用登入後門。[Apple 送審準備](https://developer.apple.com/app-store/review/)

上述步驟按依賴推進，不指定上市日期。不能靠把代幣改稱積分、移到網頁再回寫 App 權益，或審核後遠端開啟未披露功能來成立本方案。獨立 Lab 是另外的產品邊界，並非 iOS 發幣的出口。
